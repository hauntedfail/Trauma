# Task 16c.3: Importer Integration And Fallback Contract

## Goal

Replace the current custom article extraction path in `importUrl()` with the
Defuddle adapter while preserving importer security, local Markdown safety, and
fallback behavior.

## Ownership

Primary files:

- `src/server/importer/index.ts`
- `src/server/importer/extractor.ts`
- `tests/server/importer/importer.test.ts`
- `tests/server/memories/add-memory.test.ts`

Optional files:

- Create: `src/server/importer/host-policy.ts` if importer fetch and imported
  display URLs need to share the same public-host policy.
- Create: `src/server/importer/markdown-safety.ts` if Markdown serialization
  grows beyond the extraction adapter.
- Test: `tests/server/importer/markdown-safety.test.ts`

## Integration Rules

- Keep `normalizeImportUrl()`, `createPinnedFetch()`,
  `fetchWithValidatedRedirects()`, timeout handling, max-byte handling, and
  content-type checks in the importer fetch boundary.
- Call the Defuddle adapter only after HTML response text has been read within
  the size and timeout limits.
- Keep `MINIMUM_READABLE_BODY_LENGTH` or replace it only with a named constant
  that has equivalent tests.
- Map blank or too-short extracted Markdown to `link_only`.
- Map adapter errors to `link_only` with an extraction error that is useful but
  does not leak stack traces.
- Preserve `ImporterResult` shape so `addMemory()` does not need a large rewrite.

## Markdown Safety Rules

Defuddle output is still untrusted imported content. Defuddle should select and
clean the article HTML, but persisted `CONTENT.md` must be generated by a
project-owned Markdown serialization boundary unless direct Defuddle Markdown is
accepted by a separate safety review.

The PR must keep or replace the current tests that prove:

- `javascript:` links do not become active saved Markdown links.
- URL userinfo is not persisted in display URLs.
- unsafe image URLs are not persisted.
- text-node Markdown syntax cannot create active links or HTML injection.

## Tests

Update `tests/server/importer/importer.test.ts` to cover:

- Success path using a realistic HTML article fixture.
- Fetch failure still returns `link_only`.
- Non-OK response still returns `link_only`.
- Non-HTML response still returns `link_only`.
- Oversized response still returns `link_only`.
- Defuddle blank extraction returns `link_only`.
- Defuddle thrown error returns `link_only`.
- Private URL and private redirect protection still reject or fall back exactly
  as before.
- Unsafe links/images remain safe in saved Markdown or are neutralized before
  render.

Update `tests/server/memories/add-memory.test.ts` only where fixture Markdown
changes because Defuddle output differs from the previous custom converter.

## Acceptance Criteria

- `importUrl()` no longer uses the old regex/string article extraction path for
  production extraction.
- Existing importer SSRF and fetch guards remain covered by tests.
- Existing link-only fallback semantics remain covered by tests.
- `addMemory()` continues to receive the same `ImporterResult` contract.
