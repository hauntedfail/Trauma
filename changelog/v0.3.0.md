# TRAUMA 0.3.0

TRAUMA 0.3.0 adds Brilliant, the Codex app-server based translation workflow
for reader content. This release adds translation job persistence, streaming
progress, translated reader routes, Codex authentication setup, and the workflow
contracts that define the feature's implementation and recovery behavior.

## Added

- Added Brilliant translation jobs, chunks, current-translation metadata, and
  translated reader projection storage in SQLite with bundled migrations.
- Added a Codex app-server client for Unix-socket based communication, Codex
  authentication state checks, device-code login flow support, and model/default
  settings endpoints.
- Added Markdown block parsing, segment generation, prompt construction,
  structure-fingerprint validation, retry handling, stitching, and atomic
  persistence for translated `CONTENT.md` files.
- Added translation start, status, cancel, current-variant, and server-sent
  event routes for memory translation jobs.
- Added reader UI controls for starting translations, tracking progress,
  canceling active jobs, opening translated variants, and returning to the
  original source reader.
- Added translated reader routes at `/memories/:langCode/:id`, including
  source/translation variant state in reader loaders and route data.
- Added variant-local Flashback and Moment support so translated reader variants
  can keep their own anchors without mutating the source variant.
- Added the `reader-translate` agent skill and focused Brilliant workflow docs
  covering architecture, state machines, API/SSE contracts, chunking, prompt
  validation, cancellation, purge policy, and verification.
- Added Sawyer finalizer rules and a repository whitelist for local scratch
  files that must not be committed by release or review agents.

## Changed

- Reworked the settings surface to include translation target language, Codex
  app-server authentication, Codex defaults, and model metadata.
- Reworked reader data loading so source and translated variants share the
  existing reader surface while preserving variant-specific route state.
- Reworked Flashback browse, export, toggle, and delete flows to understand
  variant identity instead of assuming source content only.
- Reworked backup behavior so translation writes and translated-content updates
  have explicit backup reasons and tracked storage paths.
- Reworked Task 19 documentation into the Brilliant workflow set, moved older
  Task 18 workflow material into the archive, and split Brilliant contracts by
  ownership domain.
- Reworked the package version to `0.3.0` for this release.

## Fixed

- Fixed translation startup edge cases around invalid memory ids, stale source
  snapshots, active-job reuse races, request-language mismatches, and completed
  job immutability.
- Fixed cancellation behavior so pending jobs terminate cleanly, active chunks
  observe cancellation, and canceled waiters do not leave dangling promises.
- Fixed Codex app-server stream cleanup, disconnect handling, stable protocol
  mapping, and auth setup failure paths.
- Fixed translated Markdown validation to preserve source structure, reject
  malformed final output, strip frontmatter BOMs, and surface retry diagnostics.
- Fixed reader route loading so translation settings can be read without
  requiring Codex auth status checks on normal reader pages.
- Fixed Flashback and Moment route/database issues found during translation
  integration, including database lifetime, migration hash stability, and
  variant-scoped marker behavior.

## Verification

- Release CI runs `bun run verify` and `bun run test:e2e` before publishing the
  GitHub Release for `v0.3.0`.
